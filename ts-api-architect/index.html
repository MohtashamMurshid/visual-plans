The proof loop.

Tests first; model opinions second

What gets scored.

A clean pass is not one number

Deterministic reality

  • Hidden integration and regression tests.
  • tsc --noEmit, lint, bounded command logs.
  • Unsafe TypeScript scan: any, ignores, unsafe casts.
  • Boundary scan: no ORM/DB dependency in HTTP routes.

Architecture review

  • Local module convention and dependency direction.
  • Thin routes; validation at I/O boundaries.
  • Domain invariants and error-contract consistency.
  • Minimal change; no speculative abstraction.

Pilot

The fixture set.

Different failure modes, not five CRUD clones

Vertical slice

  • Project invitations — route → validation → use case → repository.
  • Targets auth, thin transport, response serialization.

Existing module extension

  • Team membership — follow established local pattern.
  • Targets duplicate policy and error mapping.

Bug fix

  • Billing webhook — idempotency and trust boundary.
  • Targets minimal correct change.

Cross-module change

  • Project archive — transaction and authorization rules.
  • Targets consistent domain behavior.

Refactor

  • Search filters — preserve behavior while simplifying.
  • Targets over-abstraction and regressions.

Calibration patches

  • Gold patch + deliberately bad but plausible alternatives.
  • Targets judge reliability and self-preference bias.

Judge each other—safely.

Cross-model review, not model theatre

Required controls

  • Random A/B ordering and no provider/model names.
  • Gold patches, trap patches, and two human reviewers for calibration.
  • Judge invalidity is recorded, never silently repaired.

Report honestly

  • Functional pass@1 and invalid-run rate.
  • Cost per clean pass and latency.
  • Judge agreement, disagreement outliers, and self-preference rate.

Risks worth managing.

Before we create a leaderboard

Overfit to one style

  • Use local consistency as the standard, not universal “clean architecture”.
  • Expand framework/API patterns only after v0 has signal.

Tool inequality

  • Run a strict equal-tools condition first.
  • Label any richer provider-specific agent condition separately.

Judge bias

  • Use anonymization, calibration, and human audit.
  • Never let judge score override executable gates.

Cost drift

  • Set an upfront USD cap and max turns per run.
  • Stop at the cap; follow pre-registered rerun policy.
