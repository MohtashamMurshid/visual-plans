Doomed from the Start

LLM agents leak tokens into trajectories that are already unlikely to recover. This paper reads the model’s hidden state during the first six rounds, aborts likely failures, and controls how many eventual successes may be lost.

The thesis

The model knows before its behaviour shows. A tiny linear probe can detect eventual failure from internal activations earlier than cheap trace features, so the system can stop doomed runs while a calibrated cascade protects successful ones.

Deployment blueprint.

How to turn the paper into a real system

01

Instrument inference

Capture one final-action-token hidden vector at the selected layer during each of rounds 1–6. Benchmark extraction overhead before claiming net savings.

Validate: hidden-state shape, per-round timing, token accounting
Build
02

Collect grouped trajectories

Log complete episodes with task IDs, per-round hidden vectors, generated tokens, and final binary success. Keep task groups disjoint across train, calibration, validation, certification, and test.

Validate: no task leakage; enough successful certification episodes
Data
03

Fit and calibrate

Train one standardised logistic probe per gate round, calibrate conservative thresholds with Clopper–Pearson, then search the six-round budget vector against the global recall target.

Validate: replay simulator reproduces recall and saved-token accounting
Offline
04

Freeze and certify

Lock the chosen probes, thresholds, and budgets before touching the independent certification set. Deploy only when the global lower bound clears ρ*.

Validate: immutable artefact hash; certificate report; no-abort fallback
Gate
05

Shadow, then canary

First score without aborting. Compare predicted savings, realised successes, latency, and dollars. Canary only after drift and overhead checks pass.

Validate: recall floor, p95 latency, GPU memory, cost per successful task
Deploy

What is not proven yet.

Read before production

01 · Shift

In-domain only

Grouped task splits prevent leakage, but category-held-out and zero-shot transfer remain untested. Probe, thresholds, and control must be refreshed under distribution shift.

02 · Systems cost

Tokens are not dollars

The paper measures generated-token savings, not wall-clock latency or serving cost. Hidden-state extraction has non-zero overhead and vLLM constraints.

03 · Utility

Saved compute is not reward

Reallocating aborted compute to retries or extra samples was not evaluated end to end.

04 · Reproduction

Code is pending

The paper says code will be released soon. Treat implementation details as a blueprint until the authors’ artefacts are available.

Engineer’s take.

Three practical conclusions

01

Use internal probes when you own the serving stack. They surface recoverability before cheap behavioural monitors do.

02

Optimise a sequence, not a threshold. Recall risk accumulates across rounds; independently “safe” gates do not guarantee safe episode-level recall.

03

Make abstention a feature. When signal or positive data is weak, a near-no-op policy is the correct failure mode.

Recommended next experiment.

For a real agent platform

Pilot

Run the cascade in shadow mode on one expensive, repeatable agent workflow.

Start with a 95% global recall target. Report token savings beside wall-clock and dollar savings, hold out task categories—not only task IDs—and compare against a behaviour-only monitor plus “always retry once” economics.
